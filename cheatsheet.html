03ArchitectureAct 2 · ○ Extended~60 с
Мета
Теоретично, без плам'я коду: ЩО входить, ЩО відбувається, ЩО виходить. Закласти security-історію (trust-зони) + назвати архітектуру точно: harness, spec-driven.
Кажеш
"Idea goes in as untrusted input. A harness — a factory that runs the autonomous steps — turns it into a native app. It's spec-driven: a written spec with acceptance criteria, not a prompt, drives the design, the code and the tests that verify it. And it's isolated by design — the AI only ever proposes; it returns data and never touches the machine. The harness validates every token across three sealed zones."
Акценти
  • Якщо час тисне (lightning) — пропусти цей слайд; security все одно прозвучить на 06.
  • Новий кадр: фабрика — це harness (довірений оркестратор, що проганяє кроки): «the model proposes, the harness disposes». AI повертає лише дані (JSON), shell не отримує.
  • Бейдж ✓ Spec-driven: специфікація з критеріями приймання (а не промпт) керує дизайном/кодом/тестами — підкріплююча рамка, не контраст із vibe-coding.
  • Для технічного клієнта тут можна затриматись на 3 trust-зонах.
  • Опційний спіч (не на слайді): «On a prior project I was the harness; in ESDLC the harness is code.»
Перехід → «And you watch all of that happen on one screen.»

Складні питання · тримай напоготові

«Це справді автономно, чи ви дописали руками?»
A: Агент лише повертає дані — жоден рядок застосунку не пише людина. Збирає все довірений код. На дашборді (слайд 04) видно живі стадії. За бажання — запустимо один ран прямо зараз на стенді.
«Наш код / IP у безпеці? Що з доступом AI до машини?»
A: AI ніколи не отримує оболонку (shell) на машині. Він пропонує — виконує й валідує кожен токен довірений код, у трьох ізольованих зонах. Це enterprise-safe за дизайном, а не за домовленістю.
«Скільки це коштує?»
A: У цих ранах — ~$3–6 модельного часу на апку, ~20 хв. Інженерного нагляду майже нуль. Для масштабу: 10 апок — це десятки доларів, не людино-тижні.
«А Android / Web?»
A: Архітектура платформо-незалежна. Сьогодні підключено iOS; Android і Web — розширення того самого движка, не переписування з нуля.
«Воно будує реальні складні апки чи тільки іграшки?»
A: Сьогоднішній фокус — сфокусовані нативні апки (1000–1700 рядків, реальний дизайн-систем, тести, брендинг). Для великих продуктів модель інша: вбудувати движок у команду, щоб прискорити розробку, а не замінити її.
«Виглядає як типовий AI-дизайн?»
A: Ні — вбудований дизайн-систем (Midnight Ember) задає якісну планку структурно. Поверни на слайд 05: це дефолтний вигляд, а не ручна робота.
«А якщо ідея поза можливостями движка?»
A: Він чесно відмовляється (наприклад, коли потрібен живий мережевий API), а не вдає й не падає. Прозорість меж — частина надійності.
«Хто це підтримує? Справді один розробник?»
A: Так — це і є productize-вектор: один інженер оперує «фабрикою» застосунків. Саме тому ми говоримо про це як про продукт, а не послугу.
